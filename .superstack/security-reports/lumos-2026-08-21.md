# Lumos infrastructure security review — 2026-08-21

Scope: production infrastructure for `lumos.uno`, including nginx, the Node API,
systemd services, Docker port exposure, operational monitoring, and backups.
Application authorization and business-logic security were outside this pass.

## Result

Confidence: 8/10. The reviewed production controls are deployed and verified.

## Findings resolved

- **High — internal data services exposed on host interfaces.** MinIO and HydraDB
  ports now publish only on `127.0.0.1`. The API and Next.js server also bind to
  loopback, leaving nginx as the sole public entry point.
- **High — development MinIO credential used in production.** Deployment now
  generates a 48-character random password, restricts `.env` and the Hydra token
  to mode `600`, and the live credential was rotated successfully.
- **Medium — wildcard API CORS.** The API now allows only configured origins and
  rejects requests carrying an unapproved Origin with HTTP 403.
- **Medium — no public request controls.** Nginx now limits request bodies to
  256 KiB, throttles normal API traffic, applies a stricter repository-import
  limit, and limits concurrent connections per client.
- **Medium — missing browser security headers.** HSTS, nosniff, frame denial,
  referrer policy, permissions policy, and a narrow CSP are active over HTTPS.
- **Medium — no automated liveness or state backup.** Systemd timers now run a
  full local/public health check every five minutes and create a mode-600 nightly
  archive of irreplaceable state with seven-day retention.
- **Low — repeat deployment could re-ingest an already-ready graph.** The resume
  script now detects a ready Django graph and skips the redundant operation.
- **Low — malformed JSONL command banners could make benchmark reads fail.**
  Read-only benchmark endpoints now ignore invalid/incomplete lines; dataset
  generation invokes Python directly so future artifacts remain clean.

## Production verification

- `lumos-api`, `lumos-web`, nginx, health timer, and backup timer: active.
- `3000`, `8787`, `7687`, `8443`, `9090`, `9000`, and `9001`: loopback-only.
- `https://lumos.uno/api/health`: graph ready for `django/django`.
- Allowed CORS origin: HTTP 200 with the exact origin; unapproved origin: 403.
- 300 KiB body: 413; safe 35-request burst: 14 requests throttled with 429.
- Apex HTTPS: 200; HTTP and `www`: canonical 301 to apex HTTPS.
- Backup archive: created with mode 600 and successfully listed with `tar -tzf`.
- Dependency audit: no known vulnerabilities.
- Automated tests: 13/13; TypeScript: clean; production frontend build: passed.

## Follow-up operations

- Configure Azure Monitor alerts to notify Varun when the health service fails.
- Enable Azure VM Backup or export archives off-host. Local nightly archives
  improve recovery from application mistakes but do not protect against VM loss.
- Review nginx and systemd journals regularly; no external log retention is
  configured yet.
